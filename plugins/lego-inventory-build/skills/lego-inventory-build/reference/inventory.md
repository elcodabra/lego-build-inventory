# Инвентарь: строим только из своих деталей

Инвентарь это файл `inventory.json` со списком деталей, которые у пользователя реально есть.

```json
{ "updated": "2026-09-26T21:00:00Z", "sources": ["set 31058-1 Mighty Dinosaurs"],
  "items": [{ "id": "3001", "color": "red", "qty": 4 }, { "id": "3039", "color": "lbg", "qty": 2 }] }
```

Где лежит: `--inv <файл>`, иначе `$LEGO_INVENTORY`, иначе `$LEGO_DATA_DIR/inventory.json`, иначе `./inventory.json`. MCP-сервер хранит его в `~/.lego-build/`.

## Как наполнить

| Источник | Команда |
|---|---|
| Номера наборов | `node tools/inventory.cjs add-set 31058 10696` (нужен бесплатный `REBRICKABLE_API_KEY`) |
| Экспорт Rebrickable (My LEGO → Parts → Export CSV) | `node tools/inventory.cjs import parts.csv` |
| BrickLink XML (wanted list или inventory) | `node tools/inventory.cjs import list.xml` |
| Простой CSV, можно руками или с фото россыпи | `part,color,qty`, цвет ключом (`red`), названием (`Light Bluish Gray`, `Светло-серый`) или id BrickLink |
| Одна позиция | `node tools/inventory.cjs add 3001 red 4`, `remove 3001 red 1` |

Формат определяется сам. Цвета, которых нет в палитре движка, пропускаются и печатаются в отчете. Детали, которых нет в библиотеке движка, сохраняются, но в моделях их использовать нельзя, пока их не добавят в `src/lego.js`.

Если пользователь прислал фото кучи деталей, перепиши увиденное в CSV и покажи ему на подтверждение. Честно скажи, что счет по фото приблизительный.

## Правила проектирования под инвентарь

1. Сначала `node tools/inventory.cjs show`. Проектируй только из строк в разделе, который рисуется движком. Пара деталь плюс цвет должна быть в списке, и количество не больше, чем есть.
2. Масштаб выбирай от запаса. Посчитай, сколько деталей основного цвета, и подгони размер модели так, чтобы хватило с запасом 10-20%.
3. Внутренние детали, которые не видно в финале, бери любого цвета из того, чего много. Это обычная практика настоящих сборщиков.
4. Заменяй свободно. Два кирпича 1×2 вместо одного 1×4, стопка из трех пластин вместо кирпича, плитка вместо пластины наверху.
5. После каждой правки запускай `node tools/check-model.cjs <модель>`. Строки `MISSING` показывают, чего не хватает, а после `есть:` перечислены свободные замены (детали, которые модель еще не использует).
6. Если чего-то не хватает, а замены нет, не прячь это. Покажи пользователю список недостающего (`node tools/inventory.cjs fit <модель>`) и предложи либо упростить модель, либо докупить: `node tools/inventory.cjs bom <модель> --csv` загружается в BrickLink как wanted list.

## Проверка BrickLink не нужна

Если деталь в нужном цвете лежит у пользователя, она точно выпускалась. Проверять пару по каталогу нужно только для деталей, которые предлагаешь докупить.
